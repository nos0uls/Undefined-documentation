# Катсцены: Архитектура

Принципы работы катсценного движка: очередь экшенов, менеджмент актёров и жизненный цикл сцены.

## Концепция
Катсцена — это упорядоченная очередь структур **Action-struct**, выполняемых объектом `obj_cutsceneManager`.

## Менеджер `obj_cutsceneManager`
Центральный контроллер, управляющий состоянием сцены.

### Ключевые поля
- `action_queue`: массив экшенов для выполнения.
- `actor_map`: словарь сопоставления строковых ключей с инстансами.
- `delayed_commands`: очередь команд с отложенным запуском.

### Камера
- `global.cutscene_camera_override`: блокирует стандартное слежение за игроком.
- Управление осуществляется через tween-систему в соответствующих Action-классах.

## Жизненный цикл

### 1. Инициализация
Создание менеджера и формирование очереди через Builder-API.

### 2. Запуск (`start_cutscene`)
- Активация флага `global.cutscene_active`.
- Блокировка управления игроком (`obj_player.can_move`).
- Захват управления камерой.

### 3. Выполнение
В каждом событии `Step` менеджер:
- Вызывает `start()` для нового экшена.
- Вызывает `update()` каждый кадр до возврата `true`.
- Вызывает `cleanup()` перед переходом к следующему элементу.

### 4. Завершение (`finish_cutscene`)
- Сброс глобальных флагов.
- Восстановление управления игроком.
- Очистка `actor_map`.
- Уничтожение объекта менеджера.

## Резолвинг целей (`resolve_target`)
Движок поддерживает гибкую адресацию объектов:
- **Instance ID**: прямой идентификатор инстанса.
- **Asset объекта**: поиск первого инстанса данного типа.
- **Строковые ключи**: `"player"`, `"player_body"` или пользовательские ключи из `actor_map`.
